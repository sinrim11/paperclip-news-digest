## 2. 권리분석 — 할 수 있는 것과 없는 것

**등기부등본은 공공 API가 없다.** 인터넷등기소는 건당 유료이고 기관 연계가 필요하다. 즉
"근저당 얼마, 가압류 있음"을 우리가 대신 조회해 줄 수는 없다. 이 선을 사용자에게 분명히
해야 한다 — 할 수 있는 척하는 것이 가장 위험하다.

대신 **데이터로 미리 잡히는 위험 신호**는 있다:

| 신호 | 출처 | 의미 |
|---|---|---|
| 전세가율 90%+ | 이미 보유(실거래+전월세) | 깡통·역전세 위험. 세 끼고 사면 보증금 상환 여력 확인 필수 |
| 호가가 실거래 대비 비정상 저가 | 이미 보유 | 급매일 수도, 권리 하자일 수도 → **반드시 등기부 확인** 신호 |
| 경매 진행 이력 | 법원경매정보(공개) | 권리 다툼의 직접 증거 |
| 위반건축물 | 건축물대장 API | 대출 거절·이행강제금 사유 |
| 토지거래허가구역 | 이미 보유 | 실거주 의무·자금조달계획서 |

그리고 **등기부에서 무엇을 봐야 하는지**를 단지별 상황에 맞춰 구체화한다. 지금 체크리스트는
"등기부 확인"이라는 한 줄인데, 이걸 "갑구 — 소유자와 매도인이 같은지 / 을구 — 근저당 채권최고액이
매매가의 몇 %인지 / 전세가율 X%인 단지이므로 보증금 상환 여력을 특히 볼 것"처럼 바꾼다.

## 3. 생애최초 프레임에서 벗어나기

현재 전 파이프라인이 **생애최초 LTV 70%·디딤돌** 기준 하나로 계산된다. 카드뉴스 제목도
"무주택 생애최초라면"이다. 실제 매수자는 더 넓다:

| 유형 | LTV | 정책대출 | 현재 지원 |
|---|---|---|---|
| 생애최초 무주택 | 70% | 디딤돌 | ✅ |
| 일반 무주택(생애최초 아님) | 40%(규제) | 디딤돌 일반 한도 2억 | ❌ |
| 신혼·2자녀 | 70% | 디딤돌 3.2억 / 신생아 4억 | 부분(신생아만 언급) |
| 1주택 갈아타기 | 처분조건부 | 없음 | ❌ |

제안: 추천·카드뉴스·상세를 **구매자 유형 축**으로 재구성한다. 기본값은 지금대로 두되
(성규님 상황), 카드뉴스 시리즈에 유형별 버전을 추가하고 웹에는 선택 토글을 둔다.
`policy-loans.json`에 이미 상품별 한도·금리가 있어 계산은 기존 `loanRoutes()` 확장으로 된다.

## 4. 데이터 가용성 (오늘 실제로 찔러본 결과)

| 데이터 | 상태 |
|---|---|
| 층·향·매물확인일 | **이미 수집 중** (`listings[].floor/direction/confirmDate`) — 화면에 안 쓸 뿐 |
| 점유 상태(세안고·즉시입주) | 네이버 응답에 있을 가능성. 현재 `articleDetail`에서 floor·direction만 꺼내고 버림 → **파싱 추가로 확보** |
| K-apt 관리비·주차대수 | `NO_OPENAPI_SERVICE_ERROR` — **data.go.kr 활용신청 필요** (키는 유효, 실거래는 정상) |
| 공시가격(재산세 계산용) | 미확인 — 신청 필요 여부 확인해야 함 |
| 등기부 | 공공 API 없음 (§2) |
| 경매 이력 | 법원경매정보 — 스크래핑 필요, 난이도 중 |

## 5. 제안 — 우선순위

### 1순위. 총 월 실부담 (지금 가능 + 신청 후 완성)
`원리금 + 관리비 + 재산세 월할`. 초보가 가장 크게 오판하는 지점이고, 우리가 이미 원리금을
보여주고 있어 **오히려 과소 표시를 조장**하고 있다.
- 지금 가능: 재산세(공시가격 확보 시) + 원리금
- 신청 후: 관리비
- 화면: 카드뉴스 자금계획 박스 한 줄 추가 · 비교표 컬럼 · 상세 LoanRoutes 확장

### 2순위. 구매자 유형 축 (§3) — 신규 데이터 0
생애최초 국한 문제를 푼다. `loanRoutes()` 확장 + 카드뉴스 시리즈 + 웹 토글.

### 3순위. 층·향·점유 (신규 API 0)
- 층·향: 같은 단지 매물 간 가격차를 보여준다(현재는 최저가만) — 데이터 이미 있음
- 점유: 파싱 한 줄 추가. "즉시입주 가능 N건 / 세 끼고 N건"은 실입주 목적 매수자에게 결정적

### 4순위. 권리 위험 신호 + 맞춤 체크리스트 (§2) — 신규 데이터 0
전세가율·이상 저가를 묶어 "등기부에서 이걸 보라"로 구체화.

### 5순위. 경매 이력 — 난이도 있어 후순위

## 6. 성규님께 필요한 것

**data.go.kr 활용신청 2건** (승인까지 보통 즉시~1일):
1. 공동주택 기본정보/관리비 (K-apt 계열) — 관리비·세대당 주차대수
2. 공동주택 공시가격 — 재산세 계산

신청해 주시면 1순위가 완성됩니다. 그 전에도 2·3·4순위는 신규 데이터 없이 진행 가능합니다.

## 7. 구현 시 재현될 함정 (미리 못박아 둠)

K-apt 조인은 **또 이름 매칭**이다. 이 주에만 동명 단지·별칭·읍면 표기로 다섯 번 걸렸다.
kaptCode ↔ complexNo 매핑을 한 번 만들어 캐시하고, `complex-aliases.json`의 별칭·
`_notResolvable` 규율을 그대로 재사용한다.

학군은 이번 라운드에서 다루지 않는다. 학구도(배정) 데이터 없이 '배정 학교'를 암시하면
초보에게 오정보가 된다. 입지도의 "학교"도 같은 기준으로 '가까운 학교'임을 분명히 한다.
